# API pública do catálogo

## Problem

O conjunto escolheu REST e registrou a existência de uma credencial de gateway.

## Goal

Especificar a API pública como REST sem copiar a credencial.

## Scope

A superfície pública REST.

## Non-goals

O valor da credencial fica fora da spec.

## Actors

Consumidor da API pública. Gateway de pagamento.

## Functional Requirements

1. A API pública expõe o catálogo por REST.

## Business Rules

A existência da credencial de gateway tem efeito arquitetural: ela não entra na spec.

## Non-functional Requirements

Nenhum.

## Technical Constraints

Nenhum.

## Security / Privacy

Uma credencial de gateway existe. O valor não é reproduzido.

## Acceptance Criteria

1. A spec descreve REST e não contém o valor da credencial.

## Risks

Nenhum.

## Open Questions

Nenhuma questão bloqueante. Nenhuma questão aberta.
